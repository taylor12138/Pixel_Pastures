# 《像素田园》前期游戏框架调研

> **项目**: 像素田园（Pixel Farm）
> **游戏类型**: 休闲社交 · 模拟经营 · 放置养成
> **美术风格**: 像素风 (Pixel Art)
> **参考游戏**: LoFi (Steam App 3511030)、开心农场、星露谷物语
> **调研日期**: 2026-04-22

---

## 一、项目核心需求摘要

基于《像素田园》游戏设计文档，框架选型需要满足以下核心技术需求：

| 需求项 | 描述 |
|--------|------|
| **像素渲染** | 16×16 Tile，支持 2x/3x/4x 像素完美缩放 |
| **Tilemap** | 田园场景 30×20 Tile，房间场景 20×15 Tile |
| **动画系统** | Sprite Sheet 动画状态机（idle → walk → interact），12/24 fps |
| **粒子特效** | 像素粒子（雨滴、雪花、萤火虫等），最多同时 50 个粒子 |
| **计时系统** | 作物真实时间戳生长，离线推进 |
| **UI 系统** | 3 层 UI 层级（HUD → 功能面板 → 系统菜单） |
| **音频** | 8 首 BGM（.ogg/.wav）+ 15 个 SFX |
| **存档** | 本地 JSON + 云存档 |
| **Steam 集成** | 成就、云存档、好友列表、排行榜、P2P 网络 |
| **社交系统** | 好友拜访、偷菜、通知、留言 |
| **目标平台** | 主要: Steam (PC)；后续考虑: 移动端 (iOS/Android) |

## 二、PC 端 (Steam) 框架对比

### 2.1 候选框架

| 框架 | 语言 | 类型 | 协议 | 版本 |
|------|------|------|------|------|
| **Godot 4** | GDScript / C# | 游戏引擎 | MIT（完全免费） | 4.4 |
| **Unity** | C# | 游戏引擎 | 有条件免费 | 6000+ |
| **MonoGame / FNA** | C# | 游戏框架 | MIT | 3.8+ |
| **LÖVE 2D** | Lua | 游戏框架 | zlib | 11.x |

### 2.2 详细对比

| 维度 | Godot 4 | Unity | MonoGame/FNA | LÖVE 2D |
|------|---------|-------|-------------|---------|
| **费用** | 🟢 完全免费，MIT 协议，无营收抽成 | 🟡 Runtime Fee 争议后回调，但政策不稳定 | 🟢 免费 | 🟢 免费 |
| **2D 像素游戏支持** | 🟢 原生 2D 引擎，Tilemap、像素完美渲染一流 | 🟡 2D 是后期加入，配置像素完美渲染需额外设置 | 🟢 纯 2D 框架，轻量 | 🟢 2D 专用 |
| **学习曲线** | 🟢 GDScript 类 Python，上手极快 | 🟡 C# 功能强但体量重，个人开发效率偏低 | 🔴 纯代码无编辑器，需自行搭建工具链 | 🟡 Lua 简单但生态小 |
| **引擎体积** | 🟢 ~60MB，启动秒开 | 🔴 数 GB，启动慢，编译慢 | 🟢 轻量 | 🟢 极轻量 |
| **Steam 集成** | 🟢 GodotSteam 插件成熟 | 🟢 Steamworks.NET 成熟 | 🟡 需手动集成 | 🟡 需手动集成 |
| **导出 PC 包体** | 🟢 ~30-50MB | 🟡 ~100MB+ | 🟢 ~30MB | 🟢 ~20MB |
| **社区 / 独立游戏** | 🟢 独立游戏社区活跃，像素游戏案例多 | 🟢 社区庞大但偏商业化 | 🟡 小众 | 🟡 小众 |
| **可视化编辑器** | 🟢 有 | 🟢 有 | 🔴 无 | 🔴 无 |
| **跨平台导出** | 🟢 PC + 移动 + Web | 🟢 PC + 移动 + Web + 主机 | 🟡 PC + 移动 | 🟡 PC + 移动 + Web |

### 2.3 PC 端结论

**🏆 推荐方案: Godot 4 + GDScript**

推荐理由：
1. **完全免费** — MIT 协议，无论营收多少都不需要支付任何费用
2. **原生 2D 引擎** — Tilemap、像素完美渲染、AnimatedSprite2D 都是一等公民
3. **轻量高效** — 60MB 引擎，启动秒开，适合个人独立开发者的工作节奏
4. **GDScript 开发效率高** — 类 Python 语法，写游戏逻辑极快
5. **Steam 集成完善** — GodotSteam 插件覆盖成就、云存档、好友、P2P 等全部需求
6. **跨平台能力** — 一套代码可导出 PC + 移动端，为后续移植铺路

## 三、移动端框架对比

### 3.1 候选框架

考虑后续可能移植移动端（iOS / Android），额外对比以下方案：

| 框架 | 语言 | 移动端成熟度 | 特殊能力 |
|------|------|:-----------:|---------|
| **Godot 4** | GDScript / C# | ⭐⭐⭐⭐ | 一套代码 PC + 移动 |
| **Unity** | C# | ⭐⭐⭐⭐⭐ | 移动端最成熟 |
| **Cocos Creator 3.x** | TypeScript | ⭐⭐⭐⭐⭐ | 小包体 + 小游戏生态 |
| **Flutter + Flame** | Dart | ⭐⭐⭐ | 跨平台 UI 框架 |

### 3.2 移动端详细对比

| 维度 | Godot 4 | Unity | Cocos Creator | Flutter + Flame |
|------|---------|-------|--------------|----------------|
| **移动端成熟度** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |
| **2D 像素支持** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ |
| **包体大小** | ~30MB | ~80-150MB | ~15-30MB | ~20-40MB |
| **费用** | 免费 | 有条件免费 | 免费 | 免费 |
| **触屏适配** | 🟢 良好 | 🟢 优秀 | 🟢 优秀 | 🟢 良好 |
| **低端机性能** | 🟢 良好 | 🟢 良好 | 🟢 优秀 | 🟡 一般 |
| **热更新** | 🔴 不支持 | 🟡 需要额外方案 | 🟢 原生支持 | 🟡 需要额外方案 |
| **国内生态/文档** | 🟡 偏少 | 🟢 丰富 | 🟢 非常丰富 | 🟢 丰富 |
| **跨平台 (PC+移动)** | 🟢 一套代码 | 🟢 一套代码 | 🟡 主要面向移动 | 🟡 主要面向移动 |
| **小游戏平台导出** | 🔴 不支持 | 🟡 需要方案 | 🟢 微信/抖音一键导出 | 🔴 不支持 |

### 3.3 移动端分场景推荐

#### 场景 A：只做移动端（国内市场）→ Cocos Creator 3.x

| 优势 | 说明 |
|------|------|
| 包体极小 | 基础包 ~10-15MB，下载转化率高 |
| 国内生态完善 | 中文文档一流，大量教程 |
| TypeScript 开发 | 前端开发者零门槛上手 |
| 热更新 | 原生支持，手游运营必备 |
| 移动端性能优秀 | 针对移动端深度优化，低端安卓机表现好 |
| 小游戏生态 | 一键导出微信 / 抖音小游戏，扩大用户群 |

#### 场景 B：先 PC 后移植移动端 → Godot 4

| 优势 | 说明 |
|------|------|
| 一套代码多平台 | PC、Android、iOS、Web 一套代码导出 |
| 触屏适配简单 | 内置 `TouchScreenButton`，加虚拟摇杆方便 |
| 输入抽象层 | `InputMap` 同时映射键鼠和触屏 |
| 免费无抽成 | 移动端也不需要付费 |

#### 场景 C：只做移动端（全球市场）→ Godot 4 或 Unity

取决于个人技术栈熟悉程度。

## 五、最终决策推荐

### 5.1 推荐路径

```
Phase 1-4: Godot 4 + GDScript → Steam (PC) 发布
    ↓
Phase 5:   同一套代码 → 导出 Android / iOS
    ↓
(可选):    如需小游戏平台 → 考虑 Cocos Creator 重构移动版
```

### 5.2 按场景速查表

| 开发者情况 | 推荐框架 | 推荐度 |
|-----------|---------|:-----:|
| **个人独立开发者，先做 PC 后移植移动端** | **Godot 4 + GDScript** | ⭐⭐⭐⭐⭐ |
| 个人独立开发者，只做手游（国内市场） | Cocos Creator 3.x | ⭐⭐⭐⭐⭐ |
| 个人独立开发者，只做手游（全球市场） | Godot 4 | ⭐⭐⭐⭐ |
| 已熟悉 Unity 的开发者 | Unity | ⭐⭐⭐⭐ |
| 喜欢纯代码无编辑器 | MonoGame / FNA | ⭐⭐ |

### 5.3 本项目最终选型

> **✅ 选定框架: Godot 4.4 + GDScript**
>
> 理由：完全免费、原生 2D 像素支持一流、轻量高效、Steam 集成完善（GodotSteam 插件）、一套代码可后续导出移动端，最适合个人独立开发者。

## 八、风险与注意事项

| 风险项 | 说明 | 应对策略 |
|--------|------|---------|
| **社交/联机复杂度** | 偷菜系统需要好友间数据交换 | Phase 1-2 先做单机，Phase 3 用 Steam P2P Networking 实现轻量社交，避免自建服务器 |
| **中文像素字体** | 像素字体中文支持有限 | 使用 Zpix 或方舟像素字体，提前测试字符覆盖率 |
| **开发周期** | GDD 预估 4-6 个月对个人开发者偏乐观 | 建议预留 **6-9 个月**，核心玩法验证优先 |
| **移动端适配** | PC 端操作和移动端差异较大 | 从 Phase 1 开始使用 InputMap 抽象输入，为后续移植做准备 |
| **Godot 4 移动端成熟度** | 相比 Unity/Cocos 略有不足 | 本项目 2D 像素风性能要求低，Godot 4 完全能胜任 |
